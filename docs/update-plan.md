最近在和面试官的面试过程中, 面试官对本项目提出了很多非常优秀的架构改造:

1. 项目没有考虑两个相同的文件从两个不同的客户端并发上传! 这里应该加分布式锁. 在此之上我想进一步把锁加到文件分块级别, 这样如果两个用户并发上传同文件, 还能各自传不同的分块来加快上传速度. 同时 MySQL 这边可能要对文件的哈希值和 size 建立 unique 约束, 同时在上传状态列中应该要加入 uploading 状态
2. file 微服务多实例部署, 要考虑哈希环(一致性哈希)
3. 文件冗余备份(纠错码? 冗余备份?)
4. 删除现在的双架构模式, 只自己使用磁盘, 不再使用私有 S3, 数据库默认 MySQL, 保留 sqllite 适配相关的代码和配置

对项目的改造主要体现在分布式思维和多实例部署上, 以及删除双架构.
