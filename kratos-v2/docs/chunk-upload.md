# 分块上传实现

## 概述

分块上传是处理大文件上传的核心功能，支持秒传和断点续传。

## 流程图

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│   客户端     │────▶│  CheckUpload │────▶│   Redis     │
└─────────────┘     └──────────────┘     └─────────────┘
       │                   │
       │            ┌──────┴──────┐
       │            │             │
       ▼            ▼             ▼
   秒传成功     返回已上传      全新上传
   (文件已存在)   分块列表      (从头开始)
       │            │             │
       │            │             │
       ▼            ▼             ▼
┌─────────────────────────────────────────┐
│              UploadChunk                │
│  (循环上传每个分块，跳过已上传的)          │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│              MergeChunks                │
│  1. 合并所有分块                         │
│  2. 计算MD5校验                          │
│  3. 写入数据库                           │
│  4. 发送Kafka消息异步转存OSS             │
│  5. 清理Redis和临时文件                  │
└─────────────────────────────────────────┘
```

## 秒传原理

1. 客户端计算文件完整MD5
2. 调用 `CheckUpload` 接口检查MD5是否已存在
3. 如果存在，直接创建用户文件记录（引用同一个物理文件）
4. 文件存储表使用引用计数，删除时只减引用

## 断点续传原理

1. Redis 存储每个文件的上传状态 `upload:{md5}:chunks`
2. 状态包含已上传的分块索引列表
3. 客户端从 `CheckUpload` 获取已上传列表
4. 只上传缺失的分块
5. 分块信息24小时过期

## 关键代码

```go
// 检查秒传/断点续传
func (uc *FileUsecase) CheckUpload(ctx context.Context, fileMD5 string, fileSize int64, totalChunks int32) (bool, []int32, error) {
    // 1. 检查文件是否已存在（秒传）
    store, err := uc.repo.FindStoreByMD5(ctx, fileMD5)
    if err == nil && store != nil {
        return true, nil, nil  // 可以秒传
    }

    // 2. 获取已上传的分块（断点续传）
    uploadedChunks, err := uc.repo.GetUploadedChunks(ctx, fileMD5)
    if err != nil {
        return false, nil, err
    }

    return false, uploadedChunks, nil
}
```

## 面试要点

1. **为什么用MD5？** - 快速判断文件是否相同，节省存储空间
2. **为什么用Redis？** - 高性能读写，适合临时状态存储
3. **分块大小选择？** - 5MB，平衡传输效率和失败重传成本
4. **并发上传？** - 支持多分块并行上传，提高速度
